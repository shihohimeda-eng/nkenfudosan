# SNSショート動画 編集設計ハーネス

住宅購入をテーマに、企画・編集判断・構成・台本・ファクトチェック・自己レビュー・改善を一貫して扱うための仕様とAI向け指示です。正しい情報と実体験を通じて、視聴者が自分で判断できる状態を作ります。

最重要の成果は「この人から家についてもっと学びたい」と思ってもらうこと。短期的な再生数だけを目的にしません。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| [requirements.md](requirements.md) | 目的、KPI、ターゲット、編集方針、表現ルール |
| [harness.md](harness.md) | AIへ渡す実行指示と出力フォーマット |
| [brand-philosophy.md](brand-philosophy.md) | 独自性、思想の整理状況、未確定の思想項目 |
| [account-owner-interview.md](account-owner-interview.md) | 本人への確認事項、公開範囲、承認と運用体制 |
| [fact-check-rules.md](fact-check-rules.md) | 事実確認、推測の扱い、検証結果の記録 |
| [sources.md](sources.md) | 元会話、優先情報源、参考資料・競合の登録欄 |
| [changelog.md](changelog.md) | 更新履歴、今後の拡張候補 |

## 使い方

1. requirements.mdで目的と編集方針を確認します。
2. brand-philosophy.mdとaccount-owner-interview.mdの未確定事項を確認し、回答・根拠を追記します。
3. AIにharness.mdと関連する上記ファイルを渡し、テーマ・取材メモ・参考資料などを入力します。ファイル名を書くだけでは内容が共有されない環境では、内容も添付します。
4. 出力された企画・台本・FACT CHECK・編集メモを確認します。生成物の自己レビューと、人による公開承認は別です。承認体制は未確定です。
5. 投稿結果から改善し、仕様変更をchangelog.mdに記録します。

このフォルダをそのままリポジトリに追加できます。初回コミットメッセージ例：`feat: add initial short-video editorial harness`

## 確定状況の読み方

- **仕様として整理済み**：元会話の最終仕様書に記載された内容。全項目が本人に個別承認されたという意味ではありません。
- **本人の直接指定**：速めの編集テンポ、冒頭フックと視聴維持の優先。
- **未確定／要確認**：具体値・回答・資料が未提示の内容。推測で埋めません。
- **例／今後の候補**：採用済みの実績や運用を意味しません。

元会話で提示された仕様書全52項目と、取得できた編集テンポ・ヒアリングに関する会話を再構成しています。取得範囲以前の発言や、未提供の本人資料は検証していません。出典と確認範囲は[sources.md](sources.md)を参照してください。
